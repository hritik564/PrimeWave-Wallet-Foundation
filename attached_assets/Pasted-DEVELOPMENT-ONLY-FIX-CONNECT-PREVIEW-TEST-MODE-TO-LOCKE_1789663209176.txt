DEVELOPMENT-ONLY FIX — CONNECT PREVIEW TEST MODE TO LOCKED WALLET UNLOCK FLOW

IMPORTANT:
Do NOT modify native SecureStore behavior.
Do NOT modify production wallet authentication.
Do NOT modify real wallet cryptography.
Do NOT modify signing.
Do NOT weaken any security boundary.

We have already implemented the development-only Replit Web Preview Test Mode.

The following works:

- Preview Test Mode onboarding
- Create test wallet
- Developer-defined 6-digit test PIN
- Lock
- Reset
- Preview persistence

However, there is a bug in the LOCKED WALLET → UNLOCK flow.

Observed behavior in Replit Web Preview:

1. Preview Test Mode creates a test wallet successfully.
2. Developer locks the wallet.
3. Developer enters the correct 6-digit Preview Test PIN.
4. Instead of unlocking the Preview Test Mode wallet, the UI shows:

"Preparing local vault

Checking platform-secure storage."

5. After approximately 30 seconds, it returns to the Locked Wallet screen.

This proves that the locked-wallet unlock action is incorrectly entering the real/native wallet vault/authentication path instead of the development-only Preview Test Mode path.
