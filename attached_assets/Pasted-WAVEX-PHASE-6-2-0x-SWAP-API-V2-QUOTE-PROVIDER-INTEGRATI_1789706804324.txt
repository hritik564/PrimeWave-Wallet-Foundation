WAVEX — PHASE 6.2: 0x SWAP API V2 QUOTE PROVIDER INTEGRATION

We are now implementing Phase 6.2 of the WaveX wallet roadmap.

Phase 6.1 — Swap Architecture & Quote Model — is already implemented and approved.

For Phase 6.2, integrate the current 0x EVM Swap API v2 as the first real swap quote provider.

IMPORTANT:

0x must be implemented ONLY as a provider behind the existing WaveX SwapQuoteProvider abstraction.

Do NOT redesign the swap architecture around 0x.

Do NOT bypass WaveX validation.

Do NOT allow 0x transaction data to directly reach signing or broadcasting.

This phase is primarily about obtaining and safely normalizing REAL quotes.

Do NOT implement the final Swap UI yet.

Do NOT execute swaps.

Do NOT sign swaps.

Do NOT broadcast swaps.

Do NOT add token approval execution yet.

Do NOT add Permit2 signing.

Do NOT add allowance transactions.

Do NOT add backend swap execution.

Do NOT add affiliate fees or WaveX swap fees.

Do NOT implement cross-chain swaps.

Do NOT create fake production quotes.

STOP after Phase 6.2 and wait for review.


==================================================
1. CURRENT 0x INTEGRATION
==================================================

Use the CURRENT 0x Swap API v2 EVM API.

Use the unified API host:

https://api.0x.org

Use the v2 Swap API endpoint architecture.

For this phase, use the AllowanceHolder quote endpoint:

/swap/allowance-holder/quote

Required headers include:

0x-api-key
0x-version: v2

Do NOT use the deprecated v1 API.

Do NOT use old chain-specific API hostnames.

Do NOT hardcode an API key anywhere in source code.


==================================================
2. API KEY SECURITY
==================================================

The 0x API key is NOT a wallet secret.

However, it is still an application credential and must not be committed to source control.

Create the provider configuration so the key can be supplied through environment configuration.

Use an environment variable such as:

ZEROEX_API_KEY

Do not invent a production secret.

If the environment variable is missing:

Return a clear configuration error.

Do NOT silently disable security.

Do NOT fall back to a fake API key.

Do NOT expose the API key in:

- logs
- errors
- UI
- transaction activity
- quote models
- analytics
- screenshots
- test output

IMPORTANT:

Do not put the 0x API key into a client-side persistent wallet store.

Do not store it in SecureStore as a wallet secret.

Do not store it alongside mnemonic/private-key material.

Keep the provider credential boundary clearly separated from wallet secrets.

==================================================
7. QUOTE REQUEST MAPPING
==================================================

Map:

SwapQuoteRequest
        ↓
0x quote request

The request must include the correct:

chainId
sellToken
buyToken
sellAmount
taker

Use the WaveX sender address as the 0x taker.

Do not use a different address.

Do not use a provider-controlled address.

Do not use a hardcoded wallet address.

Use exact base-unit bigint values converted safely to decimal strings for HTTP transport.

Never convert token amounts to JavaScript number.


==================================================
8. SLIPPAGE MAPPING
==================================================

WaveX uses:

slippageBps

Map it to the 0x v2 API's supported slippage parameter.

Do not convert through floating-point percentages unless the API absolutely requires it.

Prefer integer/basis-point representation throughout the mapping.

Do not silently modify the user's slippage.

Do not automatically increase slippage.

Do not allow the provider to override the user's requested slippage.


==================================================
9. HTTP CLIENT
==================================================

Create a small dedicated 0x HTTP client.

Responsibilities:

- build URL
- encode query parameters
- attach required headers
- enforce HTTPS
- send GET request
- enforce timeout
- parse response
- normalize HTTP/provider errors
- never expose API credentials

Do not scatter fetch() calls throughout SwapQuoteService.

The provider should depend on the dedicated client.

Use an injectable transport if consistent with existing architecture so tests do not require real network access.


==================================================
10. TIMEOUT
==================================================

Use a bounded request timeout.

Do not allow an indefinitely pending quote request.

Use a reasonable default consistent with existing WaveX RPC timeout philosophy.

Make the timeout configurable internally without allowing arbitrary unbounded values.

Timeout must normalize to:

SWAP_QUOTE_UNAVAILABLE

or another appropriate existing swap-specific error.


==================================================
11. HTTP ERROR HANDLING
==================================================

Handle at least:

400
401
403
404
408
429
500
502
503
504
network failure
timeout
malformed JSON

Normalize them into safe WaveX swap errors.

Do not expose:

- API key
- Authorization headers
- full credential-bearing URLs
- raw sensitive request headers
- giant provider response bodies

Do preserve enough sanitized information for debugging.

For rate limiting, preserve a normalized indication that the provider is rate limited.

Do not automatically retry in this phase unless the retry is deterministic, bounded, and clearly justified.

Prefer NO automatic retry for quote requests initially.


==================================================
12. RATE LIMITING
==================================================

Do not create an aggressive retry loop.

Do not hammer 0x.

A failed request must not recursively trigger additional requests.

If 429 is returned:

Return a normalized provider-rate-limit error/state.

Do not silently retry indefinitely.

==================================================
14. EXPECTED BUY AMOUNT
==================================================

Map the provider's buy amount into:

expectedBuyAmount

Use bigint.

Never use number.

Never round.

Never truncate.

Never use floating-point arithmetic.


==================================================
15. MINIMUM BUY AMOUNT
==================================================

Map or calculate minimumBuyAmount ONLY when the provider response and requested slippage semantics allow doing so safely.

IMPORTANT:

Do not blindly calculate minimumBuyAmount from a displayed price.

Do not use floating point.

If the provider response already provides a minimum buy amount, validate and preserve it.

If it does not, use exact integer arithmetic consistent with the provider's documented slippage semantics.

If safe derivation is not possible from the returned data:

mark it unavailable and reject the quote if WaveX requires a minimum amount for execution safety.

Do NOT fabricate it.


==================================================
16. LIQUIDITY AVAILABILITY
==================================================

If the 0x response indicates:

liquidityAvailable = false

do not construct a usable SwapQuote.

Return a normalized:

SWAP_QUOTE_UNAVAILABLE

or equivalent no-liquidity state.

Do not present a fake quote.

Do NOT automatically execute approval transactions.

Do NOT automatically request token allowances.

For this phase, preserve allowance requirements as quote metadata only.
