2. CORE NON-CUSTODIAL SECURITY INVARIANT
==================================================

The following invariant is absolute:

"WaveX Wallet must be strictly non-custodial. Private keys and recovery phrases must never leave the user's device and must never be transmitted to, stored by, logged by, or recoverable through PrimeWave/WaveX backend infrastructure."

Verify that this remains true across ALL Phase 8 components.

Specifically search for any path by which backend infrastructure could receive, persist, log, infer, reconstruct, or return:

- seed phrases
- private keys
- raw private key material
- wallet PINs
- SecureStore contents
- vault keys
- encryption keys
- signing capabilities
- raw signed transactions
- sensitive authentication material

Also verify that backend endpoints cannot accidentally become a custody/signing/broadcasting mechanism.

If any possible path exists, classify it as a security finding.

==================================================
3. MOBILE ↔ BACKEND TRUST BOUNDARY
==================================================

Audit the boundary between:

WaveX Mobile
        ↓
Backend API
        ↓
Database
        ↓
External providers/RPCs

Verify:

- mobile never sends secrets
- backend never requests secrets
- backend never requires private signing
- backend never performs wallet signing
- backend never broadcasts user transactions on behalf of the wallet
- backend cannot silently switch a user's wallet network
- backend cannot modify local wallet state
- backend cannot authorize a transaction
- backend cannot bypass the mobile authentication/signing flow

Pay particular attention to whether any newly added API could accidentally weaken an existing Phase 1–7 security boundary.
