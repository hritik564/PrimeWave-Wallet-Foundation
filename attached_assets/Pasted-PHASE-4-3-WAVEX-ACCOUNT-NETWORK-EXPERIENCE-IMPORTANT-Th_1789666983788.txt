PHASE 4.3 — WAVEX ACCOUNT & NETWORK EXPERIENCE

IMPORTANT:
This is a controlled UI + application-state phase.

PRODUCT NAME:
WAVEX

Do NOT display “PrimeWave Wallet” as the product name.
Do NOT display “by PrimeWave” in the WaveX product branding.

PrimeWave remains the ecosystem/network name where applicable.

==================================================
OBJECTIVE
==================================================

Build the WaveX account and network experience.

The goal is to make the wallet's:

- current account
- public address
- account identity
- current network
- network list
- network status
- network selection

feel like a real production wallet.

Use the existing wallet, account, and EVM network architecture.

Do NOT invent blockchain configuration.

Do NOT weaken security.

Do NOT expose secrets.

==================================================
VISUAL REFERENCE
==================================================

Continue following the attached WaveX Wallet UI reference image used in Phase 4.2.

Use it as the visual language for:

- dark futuristic interface
- cyan / electric blue / violet accents
- premium cards
- subtle glow
- rounded surfaces
- thin borders
- clean typography
- compact controls
- polished mobile interaction
- professional Web3 wallet aesthetic

Existing centralized WaveX theme tokens take priority.

Do not blindly copy example data from the image.

==================================================
1. ACCOUNT EXPERIENCE
==================================================

Create a production-style account control accessible from the WaveX Home header.

The account control should display:

- account name
- account index
- shortened public address
- account status

Example presentation:

Account 1
0xf39F...2266

Use actual public account state where available.

Do NOT display:

- mnemonic
- seed phrase
- private key
- PIN
- authentication credentials
- signing capability
- SecureStore contents

==================================================
2. ACCOUNT PANEL
==================================================

Create an account panel/modal/sheet consistent with the WaveX visual language.

It may contain:

- current account identity
- full public address
- copy address
- account index
- wallet lock action
- close action

Copying the public address is allowed.

Do NOT copy or expose any secret material.

Do NOT implement account import.

Do NOT implement account creation.

Do NOT implement account switching yet unless the existing public account architecture already supports safe selection without changing wallet security state.

If account switching is not fully supported, show a controlled future state instead.

==================================================
3. COPY ADDRESS
==================================================

Implement copy-to-clipboard for the PUBLIC wallet address only.

Requirements:

- copy only the public address
- provide visible confirmation
- sanitize any logging
- do not copy secrets
- do not place mnemonic/private keys/PINs into clipboard

If the existing security architecture has sensitive clipboard handling, reuse it where applicable.

==================================================
4. ACCOUNT ADDRESS DISPLAY
==================================================

Use a safe address-shortening helper.

Example:

0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266

→

0xf39F…2266

Ensure:

- deterministic output
- valid Ethereum addresses
- sensible behavior for short/invalid input
- no mutation of the underlying address

==================================================
5. NETWORK EXPERIENCE
==================================================

Create a network selector accessible from Home and/or the network card.

It should show the existing registered networks from the EvmNetwork registry.

Current registry includes the existing supported networks such as:

- PrimeWave
- Ethereum
- BNB
- Polygon
- Arbitrum
- Base
- Optimism

Use the actual NetworkRegistry.

Do NOT create a second network list.

==================================================
6. NETWORK LIST
==================================================

Create a polished network-selection sheet/modal.

Each network entry may display:

- network name
- chain ID
- native currency symbol
- environment
- configured/unconfigured status
- enabled/disabled status
- selected state

Do not expose internal implementation details unnecessarily.

Use clear visual status indicators.

==================================================
7. PRIMEWAVE NETWORK
==================================================

PrimeWave remains the intended primary/default network when properly configured.

IMPORTANT:

Do NOT invent production PrimeWave values.

Do NOT invent:

- chain ID
- RPC endpoint
- explorer URL
- native currency
- production environment values

If the current registry marks PrimeWave as placeholder/unconfigured:

display it honestly as:

Unconfigured
or
Not configured

Do not make it appear production-ready.

==================================================
8. NETWORK SELECTION RULES
==================================================

Use the existing EvmNetworkEngine / NetworkRegistry.

Selection must:

1. validate the network exists
2. validate it is enabled
3. validate it is configured for the requested environment
4. validate network identity
5. update active network state through the existing network abstraction
6. cause the UI to reflect the selected network

Do NOT bypass the network engine.

Do NOT modify network configuration directly from UI.

Do NOT construct network objects inside UI components.

==================================================
9. UNCONFIGURED NETWORK BEHAVIOR
==================================================

An unconfigured network must not become active for blockchain operations.

If the user taps an unconfigured network:

show a controlled state such as:

“Network not configured yet.”

Do not silently select it.

Do not create fake RPC calls.

Do not fabricate balances.

Do not fabricate network activity.

The existing PrimeWave placeholder must remain protected by this rule.

==================================================
10. NETWORK CHANGE SAFETY
==================================================

When switching between configured networks:

the active network context must change explicitly.

The UI must not silently retain stale asset data from the previous network.

After network change:

- invalidate/refresh the portfolio view
- request fresh read-model data for the newly selected network
- show loading state where necessary
- show unavailable state when appropriate

Do not merge old and new network balances.

Do not show previous-network balances under the new network.

==================================================
11. NETWORK + ACCOUNT ISOLATION
==================================================

All displayed assets remain scoped to:

account + network

Example:

Account 1 + Ethereum

must never be confused with:

Account 1 + BNB

or:

Account 2 + Ethereum

The selected network must always be visible somewhere in the relevant wallet context.

==================================================
12. NETWORK STATE
==================================================

Represent network states clearly:

- selected
- enabled
- disabled
- configured
- unconfigured
- unavailable

Do not collapse all states into one generic status.

A network being registered does not necessarily mean it is configured.

A network being configured does not necessarily mean it is currently selected.

==================================================
13. CHAIN ID
==================================================

Display chain ID where useful in the network selection UI.

Use the existing authoritative EvmNetwork chain ID.

Do not calculate or infer chain IDs.

Do not modify chain IDs from UI.

==================================================
14. ENVIRONMENT
==================================================

Respect existing environment handling:

- development
- testnet
- mainnet

Do not add new environments.

Do not expose development/testnet as production networks without clear labeling.

Do not change production configuration.

==================================================
15. HOME INTEGRATION
==================================================

Update Home so that:

- current account is accessible
- current network is accessible
- network selector opens correctly
- account panel opens correctly
- selected network is reflected in Home
- portfolio refreshes after a legitimate network change

Do not duplicate portfolio logic.

Home should continue consuming:

PortfolioReadModelService

==================================================
16. ASSETS INTEGRATION
==================================================

Assets must respond correctly to network context.

When network changes:

Assets should:

1. invalidate previous network presentation
2. request the new account/network read model
3. show loading
4. display the new network's assets
5. never display stale previous-network assets as current

Do not merge assets from different networks.

==================================================
17. NETWORK SWITCHING AND TRANSACTIONS
==================================================

This phase does NOT implement transactions.

Do not connect network selection to:

- Send
- signing
- broadcasting
- transaction construction
- swaps
- DApps

However, the selected network must be available to future transaction flows through the existing network abstraction.

==================================================
18. DAPP SAFETY
==================================================

Do NOT implement DApp network switching.

No external DApp may silently change the active WaveX network.

Future DApp requests must go through an explicit user-controlled approval flow.

Do not add WalletConnect in this phase.

==================================================
19. ACCOUNT LOCKING
==================================================

The existing Lock action must continue to work.

When the wallet is locked:

- sensitive wallet state must remain protected by the existing security architecture
- UI must return to the locked state
- Preview Test Mode must continue using its isolated preview state

Do not modify native authentication logic.
